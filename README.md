# 文档小站 V1.4.3 RC1

纯浏览器文档工具。本版基于 V1.4.2 RC2 增加文字质量检测、局部 OCR、保守公式恢复和手机阅读模式，保留已有标题、题目、二维码、表格与图片优化流程。当前仅在开发分支供确认，尚未合并或部署。最终测试、对比和视觉检查见 reports/。

## PDF → Word 的三种模式

| 模式 | 适合 | 结果 |
| --- | --- | --- |
| 智能排版（默认） | 教材、报告等有文字层的 PDF | 重建阅读顺序、合并段落、识别标题与目录；规则表格转成可编辑 Word 表格，图、无法可靠读取的表格和部分公式保留局部截图。正文可编辑。 |
| 易于编辑 | 优先修改文字 | 重建段落和标题，不插入复杂区域截图；公式与表格结构可能丢失。 |
| 原版布局 | 扫描件或要求页面外观一致 | 每个 PDF 页面作为一张图放进 Word，逐字不可编辑。 |

页码范围可写 `1,3,5-8`，留空处理全部页面。智能排版会让新章从新页开始，其余页面自然续排；输出页数不一定等于 PDF。文字质量检测为启发式规则，仍需核对专业内容和未被检出的普通汉字错字。复杂公式和表格请核对 PDF 原件；智能排版对检测到的异常局部尝试 OCR，不能确认时保留原图，不执行全 PDF OCR。

浏览器控制台输出 `PDF → DOCX 质量统计`，包含段落、短段落、标题、目录、图片、可编辑表格、回退截图、双栏、页面节和耗时。表格的文字层若漏掉上标等内容，会保留局部截图。整页扫描图叠有文字层时仍可重建正文，独立图形依赖局部图像对象或图注；识别结果应与原 PDF 核对。扫描件在可编辑模式下会提示改用原版布局或先 OCR。

## 其他功能

- PDF → PPTX：每页一张图片幻灯片；文字不可单独编辑。
- PDF → TXT：UTF-8 文本与原 PDF 页码分隔标记。
- PDF → PNG / JPG：可选页码与清晰度，多页打包 ZIP。
- PDF 合并、拆分、旋转；图片转 PDF。
- 各任务转换完成后由用户点击独立下载按钮。更换文件、模式或页码会清除旧结果。

## 本地运行与部署

将 `index.html`、`app.js`、`word-layout.js`、`word-table.js`、`word-graphics.js`、`word-exercise.js`、`word-image.js`、`text-quality.js`、`formula-recognizer.js`、`word-quality.js`、`local-ocr.js`、`ocr-data/`、`vercel.json` 放在同一网站根目录；依赖按固定版本从 CDN 加载。运行 `python3 -m http.server 8000` 后访问 `http://localhost:8000`。不要直接双击 HTML 文件，浏览器可能阻止 ES 模块和 PDF Worker。部署到 Vercel 时使用仓库根目录。

题目按题干、A/B/C/D 选项恢复顺序。无法可靠恢复括号、上标或填空横线时，仅将该题局部保留为图片。题目页不会整页回退。统计区分正文、目录、题目、图注和公式碎片；请同时查看回退数量、可编辑性、体积及耗时，短段落比例不能单独代表质量。

完整比较见 `V1.4.2-RC1_vs_RC2.md`，视觉限制见 `RC2视觉检查报告.md`。原文字层章标题乱码、部分文字公式上下标错误，以及手机整页阅读需要放大，均仍存在；补充真值表样本还显示 RC1 已有的表格分段和边框不完整问题。RC2 仍是待审阅候选版，未达到无条件生产发布标准。

当前部署形式需要网络加载 CDN 组件；PDF 文件内容在浏览器中处理，不上传转换服务器。输入总计最多 50 MB，PDF.js 转换最多 100 页，图片结果最多 100 MB。低内存设备可先拆分。加密 PDF 请先解锁。

页面渲染使用白色背景，最大约 600 万像素、最长边 4096 像素。图片导出的清晰度选项不改变 Word/PPTX 渲染分辨率。PPTX 以所选第一页比例统一画布。尚未提供 Office → PDF 后端。

依赖：pdf-lib 1.17.1（MIT）、PDF.js 5.6.205（Apache-2.0）、docx 9.6.1（MIT）、PptxGenJS 4.0.1（MIT）、JSZip 3.10.1（MIT/GPLv3，采用 MIT）。

## V1.4.3 RC1 质量增强

基础提交为 RC2 的 ae2b77a831cf43dae6463d0b2b8c6b14d058e376，开发分支 v1.4.3-quality-fix。保留 RC2 分支，未经审核不合并、不部署。

TextQualityEngine 报告异常 Unicode、部分繁体/生僻字和技术词风险。繁体本身仅警告，不自动改写简体。局部 OCR 采用 Tesseract.js 7.0.0，最多 4 个异常区域、1200ms 等待预算。正文图像不离开浏览器。引擎加载失败、识别置信度不足、数字或否定词冲突均保留源图。局部修复不能保证检测所有语义错误。扫描页保持图像，稀疏混合页缺失的图像文字以截图保留。

FormulaRecognizer 仅接受明确公式语法或可信的字形位置证据；支持有限的上下标、进制角标、逻辑式，以及简单显式 LaTeX 分式/根号。生成 Word 原生 OMML。普通 A2 不推测为 A₂；复杂公式保留高清图片。通用 OCR 对数学的可靠性有限，不能作为单独恢复依据。

教材还原模式沿用 RC2 的内容重排，输出页数不保证等于源 PDF。手机模式使用 288×612pt 页面、14pt 页边距、13pt 正文；图片仅改变显示宽度，像素不降采样。宽表格、复杂公式、扫描页在 390px 整页视图仍可能需要放大。转换结束可单独下载 text_quality_report.json。

简单表格补充识别只接受有表题、2—4 列、稳定对齐和完整小网格；复杂表格仍保持 RC2 回退。

新测试文件：tests/v143-formulas.test.mjs、tests/v143-text.test.mjs、tests/v143-tables.test.mjs、tests/v143-fallbacks.test.mjs。原有测试文件未修改。公式测试需要 Node.js、docx 9.6.1 和 JSZip 3.10.1；可将安装目录的 node_modules 路径设置到 CODEX_PRIMARY_RUNTIME_NODE_MODULES 后执行 node tests/v143-formulas.test.mjs。其余单元测试直接使用 Node.js 执行。完整浏览器验证脚本与测试样本见验证资料包。
